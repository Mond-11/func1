# func1 — ІС «Пакети прикладних програм, розроблених на факультеті»

Консольна інформаційна система на **Haskell** для обліку пакетів прикладних програм (ППП), їхніх розробників (студентів і викладачів), графіка ознайомчих семінарів та плану демонстрацій і тестових випробувань.

Проєкт реалізовано з використанням класів типів (`class`) та їхніх екземплярів (`instance`), реляційної бази даних **MySQL 8.0** (6 нормалізованих таблиць) і повністю контейнеризовано за допомогою **Docker Compose**.

---

## Технологічний стек

* **Мова:** Haskell (GHC 9.8, Cabal 3.0)
* **Бібліотеки:** `mysql-simple`, `text`, `base`
* **СУБД:** MySQL 8.0 (`utf8mb4`)
* **Інфраструктура:** Docker, Docker Compose

## Архітектура бази даних

Схема БД (`faculty_software`) складається з **6 таблиць**:

| Таблиця | Призначення | Основні поля |
| :--- | :--- | :--- |
| `software_packages` | Пакети прикладних програм (ППП) | `id`, `name`, `version`, `description` |
| `students` | Студенти-розробники | `id`, `full_name`, `student_group`, `email` |
| `teachers` | Викладачі та наукові керівники | `id`, `full_name`, `degree`, `department` |
| `package_developers` | Зв'язок розробників із ППП | `id`, `package_id`, `student_id`, `teacher_id`, `role` |
| `seminars` | Графік ознайомчих семінарів | `id`, `package_id`, `topic`, `seminar_date`, `room` |
| `demo_tests` | План демонстрацій та тестувань | `id`, `package_id`, `event_type`, `scheduled_date`, `status` |

* Видалення ППП каскадно видаляє пов'язані записи у `package_developers`, `seminars` та `demo_tests` (`ON DELETE CASCADE`).
* Видалення студента або викладача обнуляє відповідне посилання у `package_developers` (`ON DELETE SET NULL`).

## Особливості реалізації на Haskell

* **Поліморфний доступ до БД (`DBEntity`):** визначено власний клас типів `DBEntity a` із методами `insertEntity`, `updateEntity`, `deleteEntity`, `getAll` та `formatEntity`. Кожна з 6 моделей даних реалізує власний `instance DBEntity` та `instance QueryResults`.
* **Типобезпечне видалення:** метод `deleteEntity` використовує `Proxy a` (`Data.Proxy`) та `ScopedTypeVariables`, що дозволяє уніфіковано викликати `DELETE` з єдиної функції підменю `entityMenu`.
* **Коректна робота з UTF-8:** усі текстові поля серіалізуються/десеріалізуються через `Data.Text` (`T.pack` / `T.unpack`) із примусовим `SET NAMES utf8mb4` на рівні сесії та конфігурації сервера MySQL.
* **Обробка помилок:** SQL-операції обгорнуті у функцію `runSafe` (`Control.Exception.catch`), тому порушення цілісності зовнішніх ключів або інші помилки БД не завершують програму аварійно, а виводять повідомлення й повертають користувача в меню.
* **Валідація введення:** числові та необов'язкові поля (`Maybe Int`) зчитуються безпечно через `readMaybe`.

## Вимоги для запуску

* Встановлений **Docker** та **Docker Compose** (v2).
* Локальне встановлення GHC, Cabal або MySQL **не потрібне** — усе працює всередині контейнерів.

---

## Збірка та запуск

1. **Зберіть образ додатку** (перша збірка займе 1–2 хвилини через компіляцію залежностей, подальші перезбірки кешуються):
   ```bash
   docker compose build
   ```

2. **Запустіть програму в інтерактивному режимі** (контейнер `db` підніметься автоматично, ініціалізує `schema.sql` і дочекається готовності TCP-порту):
   ```bash
   docker compose run --rm app
   ```

3. **Зупинка та повне очищення** (включно з видаленням volume бази даних — корисно для повторного імпорту `schema.sql`):
   ```bash
   docker compose down -v
   ```

## Функціонал меню

Програма має дворівневе консольне меню:
1. **Головне меню** — вибір одного з 6 розділів (ППП, Студенти, Викладачі, Участь у розробці, Семінари, Демонстрації та тестування).
2. **Підменю розділу** — універсальні CRUD-дії для обраної таблиці:
    * `1` — Переглянути всі записи
    * `2` — Додати запис
    * `3` — Коригувати запис за ID
    * `4` — Видалити запис за ID
    * `0` — Повернутися в головне меню
